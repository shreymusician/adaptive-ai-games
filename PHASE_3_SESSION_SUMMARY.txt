ARCHITECTURE IMPLEMENTED
------------------------

Validation Pipeline:
  - Event structure validation
  - Type validation (against canonical taxonomy)
  - Timestamp validation (client vs. server)
  - Payload size limits (10KB per event, 10MB per batch)
  - Sequence validation (monotonic per match)

Persistence Strategy:
  - Immutable, append-only event log
  - Atomic batch storage
  - Server-side timestamps (serverTs)
  - Unique event IDs
  - Validation status tracking

Deduplication & Ordering:
  - Primary key: matchId + seq (unique constraint)
  - Gap detection (missing sequences)
  - Out-of-order packet detection
  - Late-arrival handling (configurable window, default 10K)
  - Partial batch rejection

Database:
  - MongoDB collections designed
  - Indexes optimized for queries
  - Audit trail (eventBatches collection)
  - Session management (matches collection)

KEY DESIGN DECISIONS
--------------------

1. Events are immutable — never updated, only inserted
2. Atomic persistence — all-or-nothing batch storage
3. Deterministic ordering — sequence numbers enforce order
4. Graceful degradation — errors don't crash the pipeline
5. Detailed error reporting — per-event validation errors
6. Replay capability — events queryable by match, player, or game
7. Separate concerns — processor, store, validation as independent layers
